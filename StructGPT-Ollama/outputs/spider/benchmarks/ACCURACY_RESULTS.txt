Note: DeepSeek R1's chain-of-thought reasoning model produces extensive 
explanations and reasoning traces before the final SQL query. The verbose
output format makes direct string matching challenging. Issues observed:

- Uses plural table names (singers vs singer) in reasoning
- Extensive <think> blocks with step-by-step reasoning
- SQL queries may be split across reasoning and conclusion
- Alternative approaches suggested during reasoning

The low string-match accuracy does NOT necessarily indicate poor SQL quality,
but rather reflects the challenge of extracting clean SQL from reasoning-heavy
outputs.

To get true SQL accuracy (execution-based), you would need to:

1. Download Spider Database Files:
   wget https://yale-lily.github.io/spider/spider.zip
   unzip spider.zip
   cp -r spider/database outputs/spider/

2. Run Full Spider Evaluation:
   python evaluate_for_spider.py \
     --path outputs/spider/output_sample_qwen.jsonl \
     --db outputs/spider/database \
     --table outputs/spider/tables.json \
     --etype exec

3. This provides:
   - Execution accuracy (queries run on actual databases)
   - Component matching (SELECT, WHERE, GROUP BY correctness)
   - Difficulty-level breakdown (easy/medium/hard/extra)
